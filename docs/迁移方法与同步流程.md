# 迁移方法与同步流程

这份文档记录「蜗窝科技」从动态站点（emlog ＋ PunBB）迁到静态站（Hugo ＋ GitHub Pages）
的完整方法、脚本用法、已知坑，以及域名切换的操作步骤。目标是：即使过几年回头看，
也能照着这份文档把整件事重做一遍。

---

## 一、原站是什么

| 项目 | 情况 |
| --- | --- |
| 博客 | emlog 5.2.1（PHP），数据库表前缀 `emlog_` |
| 讨论区 | PunBB 1.4，与博客**共用同一个 MySQL 库** `wowotech`（无表前缀） |
| 主机 | 虚拟主机（港台机房），只提供 FTP，无 SSH，因此**无法执行 mysqldump** |
| PHP | **5.2.17p1**（2011 年版本，Apache mod_php）——写脚本时必须迁就它 |
| 前端 | 百度云加速 CDN/WAF（`Server: wts`） |
| 有效期 | 至 2027-05-12，到期后不再续费 |

### 三个关键发现

1. **讨论区被垃圾帖灌爆**：78,263 个主题里有 78,100 个是 2022 年涌入的阿拉伯语
   二元期权广告帖，占 99.8%。真实讨论只有 **163 个主题 / 792 帖 / 169 位发言用户**
   （2016–2019），内容是实打实的 Linux 内核技术讨论。
2. **讨论区已无法访问**：PunBB 报 `Unable to fetch guest information`，所以「保留」
   的现实含义只能是**把数据救出来做成只读存档**。
3. **每篇文章有两个地址**：`/分类/别名.html` 与 `/分类/文章id.html` 在原站都能打开，
   且旧站 sitemap 里的 526 个标签页地址占了外链的大头。保外链必须把这些形态都生成。

## 二、数据从哪里来

三份来源互相补齐，缺一不可：

| 来源 | 内容 | 获取方式 |
| --- | --- | --- |
| `recon/emlog_20250207.sql` | emlog 全表快照（20MB，2025-02-07） | 从站点插件目录 `content/plugins/kl_auto_backup_and_mail/` 下载，那是备份插件写的 |
| `recon/db_20240923.sql` | 整库 dump（102MB，2024-09-23） | 主机迁移时留下的 `dumpdata/db.sql`，是**唯一含 PunBB 论坛数据**的来源 |
| 活库导出（实时） | 最新文章与评论 | `tools/export.php` 临时端点，见下节 |

> 注：dump 里的 emlog_tag 表用的是**逗号包裹的 id 列表**（如 `,7,19,`），不是单个 gid。
> 直接当 gid 用会导致标签全部丢失。

## 三、活库怎么取（无 SSH 的变通办法）

主机只给 FTP，不能跑 `mysqldump`，所以用「临时 PHP 端点」：

```
tools/sync.py
  ├─ 生成随机 token，把 tools/export.php 渲染后经 FTP 上传到 /wwwroot/_wxsync_<rand>.php
  ├─ HTTP 请求 ...?k=<token>，把活库整库流式输出为 JSON
  ├─ 无论成功失败，立刻 FTP 删除该文件（finally 里做，删不掉会明确告警）
  └─ 把 JSON 交给 tools/convert.py
```

要点：

- **必须用 `dirname(__FILE__)`**，不能用 `__DIR__`——后者是 PHP 5.3 才有的常量，
  在 5.2 下会被当成字面字符串，于是变成 `require "__DIR__/config.php"`，报「找不到文件」。
- **`json_encode()` 只能传一个参数**（第二个参数是 PHP 5.3 才加的），
  且 5.2 没有 `JSON_UNESCAPED_UNICODE`，中文会被转义成 `\uXXXX`（合法，只是体积大些）。
- 老数据里混有非法 UTF-8 字节，`json_encode` 会直接返回 `false`，脚本里带了一个
  逐字节修复函数 `wx_utf8_fix()`。
- 论坛表用 `WHERE posted < 2022-01-01` 在 SQL 层就把 7.8 万条垃圾帖挡在门外。

### 走源站、不走 CDN

批量抓取时百度云加速会对本机 403（WAF 判定为攻击）。解决方法是走主机商给的
解析别名并带上 Host 头，`config/config.ini` 里已经配好：

```ini
fetch_url  = http://wowotech.gotoip11.com
fetch_host = www.wowotech.net
```

直接请求 `www.wowotech.net` 会被限流；走上面这个组合稳定。

## 四、一条命令完成同步

```bash
python tools/sync.py              # 完整同步：活库 → 语料 → 附件 → 构建
python tools/sync.py --offline    # 不碰线上，只用本地 dump 重建
python tools/sync.py --deploy     # 构建后自动 commit + push，交给 Actions 发布
```

各脚本职责：

| 脚本 | 作用 |
| --- | --- |
| `tools/sync.py` | 总调度：取活库、删临时端点、依次调用下面几个 |
| `tools/export.php` | 上传到主机的临时导出端点（含 token 校验，用完即删） |
| `tools/sqldump.py` | 无依赖的 MySQL dump 解析器（处理转义、多行 INSERT） |
| `tools/clean_html.py` | 把 Word 粘贴风格的 HTML 洗成可读 Markdown |
| `tools/bbcode.py` | PunBB 的 BBCode → Markdown（先转义再解析，防注入） |
| `tools/convert.py` | 生成 `content/`、`data/`、`static/archive/` |
| `tools/fetch_assets.py` | 下载正文引用的图片附件（并发 5，对原站友好） |
| `tools/check_links.py` | 验收：原站 sitemap 的 1008 个地址逐个核对 |

## 五、正文清洗规则

原站正文是早年从 Word 粘贴的，`tools/clean_html.py` 处理这些：

- 丢弃 `<o:p>`、`<v:shape>`、`<o:oleobject>`、`<!--[if gte mso 9]>` 等 Office/VML 垃圾；
- 拆掉满屏的 `<span style="line-height:1.5">`、`<span lang="EN-US">` 包裹层；
- 用 `&nbsp;` 做的中文首行缩进去掉，空段落删除；
- **标题识别**：整段被 `<strong>` 包住、字号 ≥15px、长度 <80 字 → 升级为 `##`；
- **代码块**：`<pre class="prettyprint">` 保留为围栏代码；黑底白字的内联 span
  （早年用来标代码）转成 `<code>`；
- **图片**：缩略图 `thum-xxx.jpg` 换回原图，路径保持 `/content/uploadfile/...` 不变，
  这样历史上被外部引用的图片地址继续有效；「点击看原图」那层链接与图片同源时去掉。

## 六、评论与用户的保留方式

按只读冻结处理（静态站没有后端，也无法登录）：

- 7,962 条评论按文章导出为 `data/comments/<gid>.json`，保留**父子回复关系**；
- 模板里递归渲染成嵌套列表，页面顶部注明「评论区已冻结为只读存档」；
- 评论正文先做 HTML 转义再链接化，防止老评论里的脚本被当标签执行；
- 「留言板」是个 `type=page` 的页面，它的 425 条评论同样保留
  （早期版本按 `type=blog` 过滤，会静默丢掉这些数据）；
- **隐私**：公开的 SQLite 存档里**不含邮箱和 IP**；含个人信息的完整版留在本地
  `../wowotech-archive-private/wowotech-archive-full.sqlite`，不入库。
- 密码哈希（emlog 用 phpass `$P$…`、PunBB 用老式 md5）没有迁移价值，未导出。

## 七、链接处理与 URL 保留

### 统一链接规范化（`tools/normalize_links.py`）

**为什么要单独做一道工序**：正文里有大量指向 `www.wowotech.net` 的绝对地址，来源五花八门——
Word 粘贴的 HTML、PunBB 的 BBCode、评论里的裸地址、还有图片 CDN 域名
（`www.wowotech.net.img.800cdn.com`）。这些链接会把读者送回即将关闭的原站。
逐处修补治不了根，所以把所有链接规则集中到**一个脚本**里，作为固定工序执行：

```
convert.py  →  normalize_links.py  →  fetch_assets.py  →  hugo
```

规则（都定义在同一处，改规则只改这个文件）：

| 形态 | 处理 |
| --- | --- |
| 本站域名（含主机商别名 gotoip11/gotoftp11） | 去掉协议与主机，保留路径，另按下列规则还原 |
| `?post=N` | 用 `data/urlmap.json` 还原成该文章的规范地址 |
| 站内路径 | 与已知页面核对（含 `路径 + .html`、`路径/`、段落首页），命中就用规范地址 |
| 未知的站内路径 | **仍然改为相对路径**（宁可本站 404，也不跳回原站），并记入报告待人工看 |
| 图片 CDN 域名 | 取路径作为本地附件，并登记到待下载清单 |
| 非本站域名 | 一律不动（`github.com/wowotechX` 这类要保住） |

几个实现上的讲究：

- **只吃 ASCII**：中文正文里裸地址后面常紧跟中文且没有空格
  （`http://…/a.html本文描述…`），用 `[^\s]` 会把中文一起吞进链接，所以路径部分限定为
  ASCII 合法字符，句末的 `, . ; : ! ?` 匹配后再还回去。
- **跳过代码**：围栏代码块与行内代码里的地址不改，避免改坏示例。
- **评论的 `site` 字段**：有 3,790 条评论的「主页」指向本站首页，纯噪音，直接清空；
  其余外链保留。
- **幂等**：重复运行不会再次改动，可以放心放进流水线。
- **CI 门禁**：`--check` 模式下若仍有指向原站的链接，构建直接失败。

### 站内链接的二次复审（相对链接也会点不到）

第一版只处理 `https?://` 开头的绝对地址，结果 `/support_list` 这类**相对路径**永远不会被复审。
原站路由比静态站宽松，作者当年写下的地址有好几种「在原站能打开、照搬到静态站就 404」的情况：

| 原站能打开的写法 | 为什么 | 新站怎么处理 |
| --- | --- | --- |
| `/support_list`（少了 `.html`） | emlog 页面路由不要求后缀 | 补成 `/support_list.html` |
| `/linux_kenrel/bus.html` | emlog 路由**忽略分类前缀、只按 slug 找文章**（`linux_kenrel` 这个别名本身就是原站里的拼写错误） | 按文件基名反查真实地址（→ `/device_model/bus.html`）；数字基名在博客与论坛两个命名空间里会重名，按链接自身的路径前缀取舍 |
| `/forum/viewtopic.php?id=15` | 旧动态地址（论坛已停摆，原站打开是错误页） | → `/forum/15.html`；`viewforum.php` → `/forum/` |
| `/admin/#org4a2bcdd`、`/admin/#fn.1` | org-mode 导出的目录与脚注锚点，被写成了后台路径 | 改回页内锚点 `#org4a2bcdd` |
| `/xxx.html/comment-page-2` | WordPress 式后缀 | 剥掉尾巴指回原文章 |
| `/rss.php` | 老站的订阅入口 | → `/index.xml` |

正文引用的站内资源（含作者当年传到 `/admin/` 目录的图）会被登记进下载清单，
路径保持原样即可继续用。另外 `layouts/404.html` 内置了 **slug → 文章地址**的映射，
所以来自搜索引擎、外站的老链接（分类写错、缺后缀）访问时也会被自动找回。

**结果：285 处点不到的站内链接 → 12 处**，而这 12 处逐个核对后，
**在原站本身就是 404**（文章已删除、作者写错的 slug、后台目录里已不存在的截图）。

### 三个自己踩的坑（值得记下来）

这套机制本身也修了三轮，都是「看似正确、实则误伤」的类型：

1. **URL 正则的字符集少了反斜杠**：markdown 会把下划线转义成 `\_`，而永久链接的
   **链接文字**里写的正是完整旧地址，于是正则在 `\_` 处截断，把链接文字改成了 `/basic`。
2. **评论裸路径的匹配太宽**：`/xxx/p/123.html` 这种形态的路径部分会被当成站内路径去解析，
   `https://www.cnblogs.com/rockyching2009/p/10603013.html` 这类外站链接因此被误伤。
   改成要求「前一个字符不属于 URL」之后才安全。
3. **存在性判断把 `.html` 变体也算作「存在」**：于是 `/support_list` 一开始就被判定没问题，
   补后缀的规则永远不会触发——正是用户最先报上来的那个链接。

这也是为什么它值得作为一个独立工序存在：规则写错会**静默地改坏一批链接**，
所以既要有 `--check` 门禁，也要输出「未解析清单」供人眼过一遍。

### 附件清单是派生物，不是账本

`recon/assets.txt` 会**从语料里反推**（扫描 `content/` 与 `data/` 里的资源路径）后再下载，
所以不会出现「清单和内容对不上」。踩过的坑：清单文件曾缺结尾换行，追加时把两行粘成一行，
结果造出一个畸形路径，既漏了一张图，又在本地留下一个以 `.png` 结尾的目录
（导致后续写入报 PermissionError）。

### 下载顺序：HTTP 优先，FTP 兜底

图片直接走 CDN 时，部分文件（尤其是 2025 年新增的）会 302 跳到图片 CDN 后被防盗链挡下返回
403，但文件在源站 FTP 上是存在的。所以 `fetch_assets.py` 先用 HTTP 批量取，
失败项再用 FTP 兜底（走源站别名 + Host 头，避免 WAF）。目前 1,129 个附件中仅剩 1 个取不到，
是那张评论里自己标注「图片已失效」的图。

### URL 形态对照

| 原站地址形态 | 新站怎么处理 |
| --- | --- |
| `/分类/别名.html` | 文章 front matter 的 `url` 原样指定 |
| `/分类/文章id.html` | Hugo `aliases`，生成跳转页 |
| `/文章id.html`（无分类） | 同上，每篇都补这个根路径别名 |
| `/?post=id` | `layouts/404.html` 内嵌 id→URL 映射表，命中即跳转 |
| `/分类/` 之外的分类页 `/sort/<别名>` | 脚本生成分类页（含空分类） |
| `/record/YYYYMM` | 脚本生成月度存档页 |
| `/tag/<标签名>` | 脚本生成标签页（526 个，外链占比最大） |
| `/about.html` 等独立页面 | `url` 原样指定 |

验收标准写在 `tools/check_links.py`：拿原站 sitemap 的 1008 个地址逐个核对产物文件，
当前 **1007 命中**；唯一缺失的 `/soft/501.html` 在原站本身就返回 404（未审核文章）。
这份 sitemap 同时以固定副本存在 `tools/fixtures/origin-sitemap.xml`，供 CI 回归。

## 八、GitHub Pages 与域名切换

### 现在（双跑阶段）

原站继续运行到主机到期（2027-05-12），新站同时发布在 GitHub Pages 上，随时可以在
`https://<用户名>.github.io/<仓库名>/` 预览。`.github/workflows/pages.yml` 会在
每次 push 到 `main` 时自动构建并发布，构建时用 `actions/configure-pages` 输出的
地址作为 baseURL——所以**切换域名前后都不需要改配置**。

### 切换时

1. 在仓库 Settings → Pages 里填入自定义域名 `www.wowotech.net`；
2. DNS（当前在域名注册商/主机商处）加解析：
   - `www` → CNAME → `<用户名>.github.io`
   - 裸域 `wowotech.net` → A 记录指向 `185.199.108.153`、`185.199.109.153`、
     `185.199.110.153`、`185.199.111.153`（或让裸域 301 到 www）
3. 等 DNS 生效，在 Pages 里勾选 Enforce HTTPS（证书自动签发）；
4. 观察几天没问题后停掉原主机，不再续费。

### 关于国内访问

GitHub Pages 在国内可访问但不快，符合「不需要特别快」的预期。若日后想更快，
可在不改动仓库的前提下把域名接到 Cloudflare（代理模式）或腾讯 EdgeOne，
内容是纯静态文件，换托管方就是改一条 DNS 的事。

> 注意：域名若做过国内备案，指向境外主机后备案仍挂在原接入商名下，
> 不影响访问；如果将来要接回国内 CDN，需保证备案有效。

## 九、已知坑清单

1. **PHP 5.2**：`__DIR__`、短数组 `[...]`、`json_encode` 第二参数、`hash_equals`
   全部不可用或需降级处理。
2. **CDN 的 WAF 会 403**：批量请求走 `www.wowotech.net` 会被拦，要走源站别名 + Host 头。
3. **emlog_tag.gid 是 id 列表**，不是单个 id。
4. **页面也有评论**：留言板是 page，按 `type=blog` 过滤会丢 852 条评论。
5. **附件路径不能去掉 `/content`**：真实路径是 `/content/uploadfile/...`。
6. **论坛 99.8% 是垃圾帖**：SQL 层先按时间过滤，转换层再兜一道。
7. **`_index.md` 不能写 `url: /forum/index.html`**：会和 Hugo 的段落首页冲突，
   报 `mkdir ... index.html` 失败。
8. **Hugo 弃用 API**：用 `hugo.Data`（不是 `.Site.Data`）、`locale`（不是 `languageCode`），
   避免将来升级时失效。
9. **front matter 里不要写 `type:`**：emlog 的 type 字段若原样写进 front matter，会覆盖
   Hugo 按目录推断的段落类型，导致首页 `/posts/` 筛选全部落空（页面看着正常，列表却是空的）。
   现在存为 `emlog_type` 保留原值。
10. **文件名大小写冲突**：`/process_management/PELT.html` 与 `/process_management/pelt.html`
    是两篇不同文章（原站是 Linux）。源文件已用 `PELT.md` / `pelt_502.md` 区分；
    但 Windows 本地构建时 `public/` 里这两个文件仍会互相覆盖（Linux CI 上正常，部署无影响）。
    `tools/check_links.py` 会提示这类地址，看到提示不用慌。

## 十、日常维护

- **有新评论/文章时**：`python tools/sync.py --deploy`（会取活库、重建、推送）。
- **只改模板或样式时**：直接 `git push`，Actions 会重新构建。
- **想确认没丢外链**：`python tools/check_links.py`。
- **完整备份**：`content/`（Markdown 语料）＋ `static/`（附件）＋
  `static/archive/wowotech-archive.sqlite` 就是全站；三者都在仓库里，
  任何一台机器 clone 下来都能重建。

## 十一、附：侧栏与站内搜索

原站是双栏版式，侧栏有六个模块。静态化之后它们各自变成了「构建时算好的数据 + 少量 JS」：

| 原站侧栏模块 | 静态站的做法 |
| --- | --- |
| 站内搜索（原是百度 site: 搜索） | `static/search-index.json`（542 篇的纯文本索引）＋ `/search/` 页面前端过滤 |
| 功能 | 留言板、全部评论、支持者列表、随便看看的入口 |

另外新增两个生成页：`/comments/`（按时间倒序的最新 400 条评论）与 `/nav/`（站内导航总览）。

**搜索的关键取舍**：没有后端，所以索引是构建时生成的整站纯文本（5.8 MB，GitHub Pages
会 gzip 成约 2 MB），只在搜索页加载一次、之后走浏览器缓存。多个关键词按「都要出现」处理，
中文按子串匹配不做分词——这个体量（542 篇）够用，比原来那个百度站内搜索更准。

**版式**：容器放宽到 66rem，正文仍保持约 46rem 的阅读宽度，侧栏 17rem；窄屏（≤900px）
自动堆叠为单栏，侧栏落到正文之后。顶部导航、页脚与正文同宽。

### 这一节踩到的坑

1. **Hugo 的 `jsonify` 不能直接放进 JS**。`const X = {{ ... | jsonify }};` 在 JS 上下文里会被
   转义成**字符串**，于是 `X[key]` 得到 `undefined`，脚本静默失效。必须加 `| safeJS`。
   这个坑同时影响了 404 页的找回映射表——之前我只验证了映射表「存在」，没在浏览器里点过，
   直到实测随机跳转跳到 `/random/undefined` 才暴露。
2. **`/?post=N` 在静态站上会落到首页**（200），所以 404 兜底根本不会触发。这个形式要在
   首页单独用 JS 处理。
3. **重跑 `convert.py` 会把链接打回原形**：它从原始数据重新生成语料，评论里的旧地址又回来了。
   验收脚本立刻抓到（4046 处）。现在 `convert.py` 生成完会自动调用一次链接规范化，
   保证「生成完就是干净的」，不再依赖人工记得跑第二步。
