<p>Q群里问问题不过瘾，还是来这边了</p>
<p>是一个有关v8架构下函数栈的问题，先帖代码：</p>
<pre><code>
[== Undefined ==]
/*
 * AArch64 PCS assigns the frame pointer to x29.
 *
 * A simple function prologue looks like this:
 *  sub sp, sp, #0x10
 *      stp x29, x30, 
 *  mov x29, sp
 *
 * A simple function epilogue looks like this:
 *  mov sp, x29
 *  ldp x29, x30, 
 *  add sp, sp, #0x10
 */
int notrace unwind_frame(struct stackframe *frame)
{
    unsigned long high, low;
    unsigned long fp = frame-&gt;fp;

    low  = frame-&gt;sp;
    high = ALIGN(low, THREAD_SIZE);

    if (fp &lt; low || fp &gt; high || fp &amp; 0xf)
        return -EINVAL;

    frame-&gt;sp = fp + 0x10;
    frame-&gt;fp = *(unsigned long *)(fp);
    /*
     * -4 here because we care about the PC at time of bl,
     * not where the return will go.
     */
    frame-&gt;pc = *(unsigned long *)(fp + 8) - 4;

    return 0;
}

</code></pre>
<p>Q： 注释部分：</p>
<pre><code>
[== Undefined ==]
 * A simple function prologue looks like this:
 *  sub sp, sp, #0x10
 *      stp x29, x30, 
 *  mov x29, sp

</code></pre>
<p>大概做了以下几件事：
1. sp指针自减0x10
2. 将0x29(即FP)入栈，将0x30（即LR）入栈，地址为SP
3. 将FP寄存器的值赋给SP
<strong>那么是不是意味着，对于单个函数，函数栈的大小只能是0x10？如果函数中临时变量较多超出0x10怎么办？</strong></p>
<p>之前我在x86架构下，确定一个函数的栈范围需要ESP和EBP两个指针，似乎ARM下是用FP和SP，并且FP的相邻地址就保存了LR
按照以上的说法，如果出现了系统崩溃的bug，似乎只需要知道FP指针，就可以推导函数调用的整个流程（因为相当于同时知道了LR）</p>

<p>肯定不会有问题啊：
SP自减0x10，然后将FP和LR入栈（意味着SP又减了0x8），之后再把SP赋值给FP（意味着当前函数的frame pointer是从这里开始的），于是当前函数的栈帧，就基于现在的FP，欢快的递减了。
哦……我明白了，你是不是把mov指令理解反了？是把SP给到FP，而不是把FP给到SP。</p>
