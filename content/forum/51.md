<p>任务说明
通过“<a href="/forum/">【任务2】启动到u-boot command line</a>”，已经成功初始化了板子的DRAM，并将u-boot加载到DRAM中运行至命令行。基于此，我们可以展开第三个任务：加载并启动Linux kernel（可以以点亮一个LED 灯作为任务的验收标准）。完成该任务的基本步骤包括：</p>
</li>
<li>
<p>配置并编译一个最简单的Linux kernel，使其可以在具体的板子上执行。编译成功后，将生成uImage和对应的dtb文件。[/*]</p>
</li>
<li>
<p>为了便于验证，可以在linux kernel运行的第一时间，点亮一个LED灯，以标识任务的完成[/*]</p>
</li>
<li>
<p>根据板子的实际情况，通过dfu，将uImage和dtb文件，分别下载到DRAM的指定位置[/*]</p>
</li>
<li>
<p>根据板子的实际情况，使用指定的参数，通过u-boot的bootm命令，执行linux kernel[/*]</p>
</li>
<li>
<p>涉及的知识点
该任务主要涉及如下知识点：</p>
</li>
<li>
<p>Linux kernel的启动流程（和具体的平台有关，我们会先以ARM64为例）[/*]</p>
</li>
<li>
<p>Linux kernel的配置（只需要掌握并理解最基本的即可）[/*]</p>
</li>
<li>
<p>Linux kernel最简单的移植（包括物理地址、虚拟地址等概念，device tree移植等）[/*]</p>
</li>
<li>
<p>Linux kernel的编译，以及uImage的生成[/*]</p>
</li>
<li>
<p>u-boot中boot linux kernel的要求、流程以及操作步骤[/*]</p>
</li>
<li>
<p>完成任务的思路
该任务可以拆分为几个独立的部分：</p>
</li>
<li>
<p>Linux kernel启动流程中和平台相关部分的分析，针对不同的平台，可以写一系列的文章。我们已经完成了ARM64的分析，具体可参考博客中“ARM64的启动过程”系列文章[/*]</p>
</li>
<li>
<p>linux kernel的配置解析，这是观察linux kernel的另外一个视角。可以以具体的平台为单位，写一系列的分析文章[/*]</p>
</li>
<li>
<p>linux kernel平台相关部分的移植说明，根据实际的硬件情况，写一篇文章即可[/*]</p>
</li>
<li>
<p>linux kernel device tree的移植说明，结合博客上device tree的分析文章，从实践的角度，加深对device的理解[/*]</p>
</li>
<li>
<p>u-boot boot linux kernel的流程及步骤说明[/*]</p>
</li>
</ol>
<p>另外，由于该任务涉及到u-boot和linux kernel的权利交接，任何一方出现问题，任务都无法完成。因此，遇到问题时的debug思路和手段，显得尤为重要，到时我们会尽量详细的记录和总结。</p>

<p>可以通过如下步骤在板子上验证：
1）代码下载（具体可参考“<a href="/x_project/bubblegum_uboot_porting.html">X-003-UBOOT-基于Bubblegum-96平台的u-boot移植说明</a>”）</p>
<pre><code>
[== Undefined ==]
mkidr -p ~/work/xprj
cd ~/work/xprj
git clone https://github.com/wowotechX/build
git clone https://github.com/wowotechX/u-boot
git clone https://github.com/wowotechX/tools
git clone https://github.com/wowotechX/linux
git clone https://github.com/wowotechX/doc    #包含有说明文档

</code></pre>
<p>2）代码编译</p>
<pre><code>
[== Undefined ==]
cd build
make env_prepare    #下载交叉编译工具，只需要执行一次，之前任务有下载过的，请忽略该步骤
make libusb             #只需要执行一次
make dfu                 #只需要执行一次
make uboot kernel uImage

</code></pre>
<p>3）按住Bubblegum-96的ADFU键，使板子进入DFU模式</p>
<p>4）按住Bubblegum-96的ADFU键不松开，将splboot.bin（就是我们的SPL image）下载到SRAM并执行</p>
<pre><code>
[== Undefined ==]
sudo ../tools/dfu/dfu bubblegum 0xe406b200 ../tools/actions/splboot.bin 1

</code></pre>
<p>5）执行完毕后，会重新进入DFU模式，进入后，可以松开ADFU按键。</p>
<p>6）将包含Kernel Image和dtb文件的FIT uImage下载DDR中（不执行）</p>
<pre><code>
[== Undefined ==]
sudo ../tools/dfu/dfu bubblegum 0x6400000 ./out/xprj_uImage.itb 0

</code></pre>
<p>7）将u-boot下载到DDR并执行</p>
<pre><code>
[== Undefined ==]
sudo ../tools/dfu/dfu bubblegum 0x11000000 out/u-boot/u-boot-dtb.bin 1

</code></pre>
<p>8）使用串口连接开发板，进入命令行后，以FIT uImage在memory中的位置为参数，执行bootm命令</p>
<pre><code>
[== Undefined ==]
bootm 0x6400000

</code></pre>
<p>即可成功启动linux kernel。</p>
<p>注：github上的kernel仓库，没有点亮LED的代码，如果需要确定kernel是否启动成功，请按照<a href="/x_project/bubblegum_uboot_booti.html">X-010-UBOOT-使用booti命令启动kernel(Bubblegum-96平台)</a>中的相关说明，修改kernel的source code。</p>

<p>看到了，关于uImage，我的思路是这样的，不知道你觉得如何：
1. 我们的编译脚本（现在的Makefile），只负责单纯的Linux kernel、u-boot等代码级的东西。因此，执行make kernel之后，只生成标准的kernel image，例如：arm的zImage、arm64的Image。
2. 然后，我们可能会要为不同的bootloader，制作该bootloader喜欢的、特殊格式的image，这个image包含了kernel image，但不限于此，例如：</p>
<blockquote>
<p>** 写道：**</p>
<p>可以包含一个或者多个dtb文件;
可以包含一个或者多个kernel image文件;
可以包含ramdisk、rootfs等等。</p>
</blockquote>
<p>因此，我倾向于把这个制作的过程，独立出来，例如可以抽象为make image，具体image的类型以及所需的参数，可以在config.mk中指定。另外，如果制作image的过程比较复杂，可以写一个脚本，然后在make image中调用。
3. 按照这个思路，以tiny210分支的改动为例，所需的改动应该是：
3-1) 在config.mk中增加相应的内容，例如：</p>
<pre><code>
[== Undefined ==]
BOARD_IMAGE_TYPE=uImage
UIMAGE_LOADADDR=...
UIMAGE_ENTRYADDR=...
...

</code></pre>
<p>3-2) 在Makefile中，增加make image的编译项目，根据config.mk中的配置想，生成所需的image。</p>
